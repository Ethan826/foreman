## New findings

1. **P1 · C4 orders the Write request before Bash, but accepts a Write that completes afterward.** Keep the canonical Write input, canonical after-snapshot, and passing Bash result. Reorder the records to `Write(toolu_01L3WRITE)`, `Bash(toolu_01L3CHECK, "sh check.sh")`, Bash result, Write result. `script_problem` requires the Write result to follow its own call and compares the two call positions. It never compares the Write **result** position with the Bash call. The Bash output can therefore be accepted as evidence of the replacement even if the replacement was still pending. A second mismatch also passes if the Write input has no final newline and the after-snapshot has one, because both are checked independently against the two variants. **Fix.** Require the successful Write result before the Bash call, validate its nonempty unique call ID, and compare the digest of that Write’s exact content with the snapshot. Keep the flagless Write shape observed on path A, and require the pinned client’s positive Write acknowledgment. The stand-in already emits one, but the scorer currently accepts even `content: "Permission to use Write has been denied."` when the flag is absent. The stricter Bash flag rule is justified for C1 and C4, where a missing flag or failed check prevents a refusal claim, and for C6, where an explicit error or exit banner scores FAIL.
